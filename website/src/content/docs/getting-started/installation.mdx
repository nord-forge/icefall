## One-liner install

```bash
curl -fsSL https://icefall.dev/install.sh | bash
```

This will:
1. Detect your OS and architecture
2. Detect or install a container runtime — Docker or Podman
3. Install Caddy (for automatic HTTPS)
4. Download the Icefall binary and dashboard
5. Generate a config file with a random encryption key
6. Create and start a systemd service
7. Print your dashboard URL

Piping a script straight into `bash` is convenient, but you should read what you
run. The full installer is reproduced below — it is the exact script served at
`icefall.dev/install.sh`.

## Install flags

The installer accepts flags and environment variables. Flags can appear in any
order after `bash -s --`.

| Flag | Environment variable | Values | Default | Purpose |
|---|---|---|---|---|
| `--runtime=NAME` | `ICEFALL_RUNTIME` | `docker`, `podman`, `auto` | `auto` | Which container runtime to use |
| `--yes` | — | — | off | Non-interactive: accept all defaults, ask nothing |
| — | `ICEFALL_VERSION` | version tag, or `latest` | `latest` | Which Icefall release to install |
| — | `ICEFALL_GITHUB_ORG` | GitHub org | `nord-forge` | Org to download releases from (forks/mirrors) |
| — | `ICEFALL_LOW_MEMORY` | `true`, `false` | auto (≤ 1.5 GB RAM) | Force low-memory mode on or off |
| — | `NO_COLOR` | any non-empty value | off | Disable colored output |

On a small server the installer's runtime prompt recommends and defaults to
Podman. To pre-answer it in an unattended install, set `ICEFALL_RUNTIME=podman`
(or `docker`) explicitly.

## Choosing a container runtime

Icefall runs your apps as containers and works with either **Docker** or
**Podman** (including rootless Podman). By default the installer auto-detects
what is available; you can also pick one explicitly. For the full comparison and
the reasoning behind the small-server recommendation, see
[Container runtime](/concepts/container-runtime).

:::tip[Small servers (1 vCPU / 1 GB): prefer Podman]
On a server with **≤ 1.5 GB RAM**, the installer detects the constraint,
**recommends Podman, and defaults to it** — Podman is daemonless and frees
~80 MB of RAM that Docker's always-on daemon would consume. It still prints both
options and lets you choose; nothing is forced. On larger servers the default
stays Docker. See the [runtime comparison](/concepts/container-runtime) for why.
:::

<Tabs>
<TabItem label="Auto-detect (default)">
```bash
curl -fsSL https://icefall.dev/install.sh | bash
```

The installer looks for a running runtime, preferring one already in use. If
**both** Docker and Podman are installed it asks which to use. If neither is
installed it prints an annotated Docker-vs-Podman comparison and prompts you to
choose. On a **small server** the prompt recommends and defaults to Podman; on a
larger server it defaults to Docker. Either way the choice is yours.

When you choose Podman, the installer sets it up **rootful** (resource limits
enforced, privileged ports available), installs `podman-compose` for Raw Compose
mode, and enables cgroups-v2 delegation so limits also work if you later switch
to rootless.
</TabItem>
<TabItem label="Force Podman">
```bash
curl -fsSL https://icefall.dev/install.sh | bash -s -- --runtime=podman
```

Use this when a server has both runtimes but you want Icefall to commit to
Podman. The installer will **not** silently fall back to Docker — if Podman is
missing it installs Podman, and if Podman cannot start it stops with an error
explaining why. Requires Podman 4.0 or newer.
</TabItem>
<TabItem label="Force Docker">
```bash
curl -fsSL https://icefall.dev/install.sh | bash -s -- --runtime=docker
```

Pins the install to Docker even if Podman is also present.
</TabItem>
</Tabs>

The runtime can also be set with an environment variable, which is convenient
for cloud-init or CI:

```bash
ICEFALL_RUNTIME=podman curl -fsSL https://icefall.dev/install.sh | bash -s -- --yes
```

:::note[Re-installs keep your runtime]
If Icefall is already installed, re-running the installer keeps the runtime
recorded in your existing `config.toml`. Pass `--runtime=` explicitly only if
you intend to switch.
:::

## Requirements

- **OS:** Ubuntu 20.04+, Debian 11+, Fedora 38+, CentOS 9+, Arch
- **Architecture:** x86_64 or aarch64
- **RAM:** 1 GB minimum, 2 GB recommended
- **Disk:** 10 GB minimum
- **Ports:** 80 and 443 open for web traffic, 3000 for the dashboard

Icefall is designed to run well on the smallest droplets *and* large servers. On
a 1 GB box, choose Podman (the installer defaults to it there) and keep
low-memory mode on — the control plane fits in ~85 MB of overhead, leaving the
rest for your apps. See [Container runtime](/concepts/container-runtime) for the
full small-vs-large guidance.

## Manual install

Releases are a tarball containing just the `icefall` binary — **the dashboard is
embedded in it**, so there's nothing else to extract, copy, or locate. Drop the
binary on your `PATH` and run it.

<Tabs>
<TabItem label="Ubuntu/Debian">
```bash
# Install Docker
curl -fsSL https://get.docker.com | sh

# Install Caddy
sudo apt install -y caddy

# Pick the tarball matching your architecture: x86_64-linux or aarch64-linux
ARCH=x86_64-linux
TAG=$(curl -fsSL https://api.github.com/repos/nord-forge/icefall/releases/latest \
  | grep -m1 '"tag_name"' | cut -d'"' -f4)

# Download and extract the self-contained binary
sudo mkdir -p /var/lib/icefall
curl -fsSL "https://github.com/nord-forge/icefall/releases/download/${TAG}/icefall-${TAG}-${ARCH}.tar.gz" \
  | sudo tar -xz -C /var/lib/icefall
sudo install -m 755 /var/lib/icefall/icefall /usr/local/bin/icefall

# Initialize
sudo icefall init

# Start
sudo systemctl enable icefall
sudo systemctl start icefall
```
</TabItem>
<TabItem label="Fedora/RHEL">
```bash
# Install Docker
sudo dnf install -y docker
sudo systemctl enable --now docker

# Install Caddy
sudo dnf copr enable @caddy/caddy
sudo dnf install -y caddy

# Pick the tarball matching your architecture: x86_64-linux or aarch64-linux
ARCH=x86_64-linux
TAG=$(curl -fsSL https://api.github.com/repos/nord-forge/icefall/releases/latest \
  | grep -m1 '"tag_name"' | cut -d'"' -f4)

# Download and extract the self-contained binary
sudo mkdir -p /var/lib/icefall
curl -fsSL "https://github.com/nord-forge/icefall/releases/download/${TAG}/icefall-${TAG}-${ARCH}.tar.gz" \
  | sudo tar -xz -C /var/lib/icefall
sudo install -m 755 /var/lib/icefall/icefall /usr/local/bin/icefall

sudo icefall init
sudo systemctl enable --now icefall
```
</TabItem>
</Tabs>

:::note[Self-contained binary]
The dashboard is compiled into the `icefall` binary, so a hand-written systemd
unit doesn't need any special `WorkingDirectory` to serve the UI — the binary is
all you need. (For local UI development, set `ICEFALL_DASHBOARD_DIR` to a
`dashboard/dist` on disk to serve from there without rebuilding the binary.)
:::

## Non-interactive install

For automated setups (CI, Terraform, cloud-init):

```bash
curl -fsSL https://icefall.dev/install.sh | bash -s -- --yes
```

Combine `--yes` with `--runtime=` to pin the runtime in an unattended install:

```bash
curl -fsSL https://icefall.dev/install.sh | bash -s -- --yes --runtime=podman
```

## Verify

```bash
icefall status
```

Should show server version, CPU, memory, and disk usage.
