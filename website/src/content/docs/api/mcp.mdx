Icefall ships a built-in [Model Context Protocol](https://modelcontextprotocol.io/)
server. It lets an MCP-capable assistant — Claude, an IDE agent, or your own
client — inspect and operate your Icefall server through a structured tool
interface, instead of you driving the dashboard or CLI by hand.

## What it exposes

The MCP server provides three kinds of capability:

- **Tools** — actions and queries the assistant can call: list and inspect
  apps, trigger deploys, read logs, manage environment variables and domains,
  provision databases, check server status, and more.
- **Resources** — readable context the assistant can pull in, such as the
  current app list, server status, and configuration.
- **Prompts** — ready-made prompt templates for common tasks.

## Connecting

The MCP server runs as part of the Icefall daemon and speaks MCP over
HTTP/JSON. Point your MCP client at:

```
https://your-icefall-server/api/v1/mcp
```

## Authentication

The MCP server uses the same authentication as the [REST API](/api/overview/):
an [API token](/api/tokens/) sent as a bearer token.

```
Authorization: Bearer icefall_xxxxxxxx
```

Create a token in the dashboard under **Settings → API Tokens**, then configure
it in your MCP client. The token carries the role of the user who created it —
the assistant can do exactly what that user can do, no more. Write tools
require the `admin` or `deployer` role; read tools work for any authenticated
user.

## Example client configuration

Most MCP clients take a server URL and a header. The two values you always need
are the URL and the `Authorization` header:

```json
{
  "mcpServers": {
    "icefall": {
      "url": "https://your-icefall-server/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer icefall_xxxxxxxx"
      }
    }
  }
}
```

<Aside type="caution">
An MCP token lets an assistant take real actions — deploying apps, changing
environment variables, provisioning databases. Treat it like any other
credential: scope it to the least-privileged role that works, set an expiry,
and revoke it the moment it is no longer needed.
</Aside>

## HTTP endpoints

The MCP capabilities are also reachable as plain HTTP routes under `/api/v1`,
which is what MCP clients call under the hood:

| Method | Path | Description |
|--------|------|-------------|
| GET | `/mcp/tools` | List tools with input schemas |
| POST | `/mcp/call` | Call a tool |
| GET | `/mcp/resources` | List resources |
| POST | `/mcp/resources/read` | Read a resource by URI |
| GET | `/mcp/prompts` | List prompts |
| POST | `/mcp/prompts/get` | Get a prompt's messages |

## Tools

Call a tool with `POST /mcp/call`, passing the tool name and its parameters:

```bash
curl -X POST https://icefall.example.com/api/v1/mcp/call \
  -H "Authorization: Bearer icefall_xxxxxxxx" \
  -H "X-Icefall-Request: 1" \
  -H "Content-Type: application/json" \
  -d '{ "tool": "deploy_app", "params": { "app_id": "app_a1b2c3", "no_cache": true } }'
```

The request body is `{ "tool": <name>, "params": <object> }`. Write tools
(marked below) require the `admin` or `deployer` role; using one without it
returns `bad_request`.

### Read tools

| Tool | Parameters | Description |
|------|-----------|-------------|
| `list_apps` | — | List all apps with status |
| `get_app` | `app_id` | Detailed info for one app |
| `get_deploy_status` | `app_id` | Current deploy status and recent history |
| `get_logs` | `app_id`, `search?`, `limit?` (default 100) | Recent logs for an app |
| `get_env_vars` | `app_id` | Env vars for an app (values masked) |
| `list_databases` | — | List managed databases |
| `get_health_status` | `app_id` | Health-check status for an app |
| `get_server_status` | — | Server CPU, memory, disk overview |
| `diagnose` | `app_id` | Logs, health, metrics, and deploys as one summary |
| `suggest_fix` | `app_id`, `issue` | Suggested next steps for a diagnosed issue |
| `list_servers` | — | All servers with health and metrics |
| `server_forecast` | `server_id` | Resource usage forecast for a server |
| `search` | `query` | Search apps, databases, servers, domains |
| `get_analytics` | `days?` (default 30) | Deploy frequency, success rate, build times |

### Write tools

| Tool | Parameters | Description |
|------|-----------|-------------|
| `deploy_app` | `app_id`, `no_cache?`, `tag?` | Trigger a deploy |
| `create_app` | `name`, `git_repo?`, `branch?` (default `main`), `framework?` | Create an app |
| `restart_app` | `app_id` | Restart an app's container |
| `set_env_var` | `app_id`, `key`, `value`, `scope?` (`shared`/`production`/`preview`) | Set an env var |
| `add_domain` | `app_id`, `domain` | Add a custom domain |
| `create_database` | `name`, `db_type` (`postgres`/`mysql`/`redis`/`mongo`) | Provision a database |
| `cancel_deploy` | `deploy_id` | Cancel an in-progress deploy |
| `rollback_deploy` | `app_id`, `deploy_id` | Roll back to a previous deploy |
| `approve_deploy` | `deploy_id` | Approve a pending deploy |
| `bulk_restart` | `project_id?`, `tag?` | Restart apps by project or tag |
| `bulk_deploy` | `project_id?`, `tag?` | Deploy apps by project or tag |
| `export_bundle` | `app_id` | Export an app as a portable bundle |

List the tools with their JSON input schemas:

```bash
curl https://icefall.example.com/api/v1/mcp/tools \
  -H "Authorization: Bearer icefall_xxxxxxxx"
```

## Resources

Read a resource with `POST /mcp/resources/read`, passing its URI:

```bash
curl -X POST https://icefall.example.com/api/v1/mcp/resources/read \
  -H "Authorization: Bearer icefall_xxxxxxxx" \
  -H "X-Icefall-Request: 1" \
  -H "Content-Type: application/json" \
  -d '{ "uri": "icefall://apps" }'
```

The response wraps the data under `contents`:

```json
{ "contents": [ { "uri": "icefall://apps", "data": [ /* apps */ ] } ] }
```

### Listed resources

| URI | Returns |
|-----|---------|
| `icefall://apps` | All apps |
| `icefall://databases` | All managed databases |
| `icefall://servers` | All servers |
| `icefall://deploys/recent` | Last 10 deploys across all apps |
| `icefall://incidents` | Active and recent incidents |
| `icefall://settings` | Non-sensitive settings (`{ "version": "..." }`) |

### Templated resources

| URI | Returns |
|-----|---------|
| `icefall://apps/{app_id}` | One app, or `not_found` |
| `icefall://apps/{app_id}/logs` | `{ "logs": [...] }` (last 100 lines) |
| `icefall://servers/{server_id}` | One server, or `not_found` |
| `icefall://servers/{server_id}/metrics` | Current CPU, memory, and disk for the server |

## Prompts

Fetch a prompt's messages with `POST /mcp/prompts/get`, passing its name and
arguments:

```bash
curl -X POST https://icefall.example.com/api/v1/mcp/prompts/get \
  -H "Authorization: Bearer icefall_xxxxxxxx" \
  -H "X-Icefall-Request: 1" \
  -H "Content-Type: application/json" \
  -d '{ "name": "deploy-app", "arguments": { "app_name": "billing-api", "branch": "main" } }'
```

```json
{ "messages": [ { "role": "user", "content": "..." } ] }
```

| Prompt | Arguments | Description |
|--------|-----------|-------------|
| `deploy-app` | `app_name` (required), `branch?` | Deploy an app with guided options |
| `troubleshoot` | `app_name` (required), `symptom?` | Diagnose a failing or unhealthy app |
| `create-app` | `repo_url` (required), `name?` | Set up a new app step by step |
| `security-audit` | — | Check for common security issues across apps |
| `setup-monitoring` | `app_name` (required) | Configure health checks and alerts |

## Error handling

MCP endpoints use the same error format as the rest of the API:

```json
{ "error": "bad_request", "message": "Unknown tool: foo" }
```

| Status | `error` | When |
|--------|---------|------|
| 400 | `bad_request` | Unknown tool, resource, or prompt; missing parameters; role lacks write access |
| 403 | `forbidden` | Authentication required to read a resource |
| 404 | `not_found` | A referenced app, deploy, or server does not exist |
| 500 | `internal_error` | Unexpected failure (details hidden) |

## When to use it

The MCP server is for letting an assistant *operate* Icefall conversationally —
"deploy the latest commit", "show me why the last build failed", "what's using
the most memory". For scripts and CI, the [REST API](/api/overview/) and
[CLI](/cli/commands/) are the better fit; they are the same capabilities
without an assistant in the loop.
