These are inbound webhooks: Git providers POST to them to trigger deploys. They
authenticate with signatures or tokens, not API credentials, so the
`X-Icefall-Request` header does not apply. For outbound notification callbacks
see the [Notifications API](/api/notifications/#outbound-webhook-endpoints).
All paths are relative to `/api/v1`.

## Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/webhooks/{app_id}/github` | signature | GitHub push webhook for an app |
| POST | `/webhooks/{app_id}/gitlab` | token | GitLab push webhook for an app |
| POST | `/github/events` | signature | GitHub App events (multi-app) |
| GET | `/github/setup` | auth | GitHub App manifest and setup |
| GET | `/github/apps` | auth | List configured GitHub Apps |
| DELETE | `/github/apps/{id}` | auth | Delete a GitHub App |

## How a deploy is triggered

A push webhook deploys when all of these hold:

1. The event is a push (`push` for GitHub, `Push Hook` for GitLab).
2. The app has a `webhook_secret` set — without one the request is rejected
   (fail-closed).
3. The signature or token validates against that secret.
4. The pushed branch matches the app's `git_branch` (production), or its
   `preview_branch_pattern` when previews are enabled (creates a preview
   environment).

Deleting a branch tears down its matching preview environment.

## GitHub push webhook

```
POST /webhooks/{app_id}/github
```

Configure this URL as a push webhook on the repository. Required headers:

| Header | Description |
|--------|-------------|
| `X-GitHub-Event` | Event type, e.g. `push` |
| `X-Hub-Signature-256` | `sha256=<hmac>` of the body, keyed by the app's `webhook_secret` |

Example payload (subset GitHub sends):

```json
{
  "ref": "refs/heads/main",
  "after": "1ab4c9d8e7f6a5b4c3d2e1f0a9b8c7d6e5f4a3b2",
  "deleted": false,
  "repository": {
    "clone_url": "https://github.com/acme/billing-api.git",
    "ssh_url": "git@github.com:acme/billing-api.git"
  }
}
```

Responses:

- `200` — processed (may not deploy if the branch does not match).
- `400` — invalid JSON.
- `401` — missing or invalid signature.
- `404` — app not found.

<Aside type="note">
The app's `webhook_secret` is what signs these requests — set it on the app,
then use the same value as the webhook secret in GitHub.
</Aside>

## GitLab push webhook

```
POST /webhooks/{app_id}/gitlab
```

Required headers:

| Header | Description |
|--------|-------------|
| `X-Gitlab-Event` | Event type, e.g. `Push Hook` |
| `X-Gitlab-Token` | Must match the app's `webhook_secret` (compared in constant time) |

Example payload (subset GitLab sends):

```json
{
  "ref": "refs/heads/main",
  "after": "1ab4c9d8e7f6a5b4c3d2e1f0a9b8c7d6e5f4a3b2",
  "project": {
    "git_http_url": "https://gitlab.com/acme/billing-api.git",
    "git_ssh_url": "git@gitlab.com:acme/billing-api.git"
  }
}
```

An `after` of all zeros signals a deleted branch and tears down the matching
preview environment. Responses match the GitHub endpoint (`200`, `400`,
`401`, `404`).

## GitHub App integration

The GitHub App flow lets one installation serve many apps, matched by
repository clone URL.

### Setup

```
GET /github/setup
```

Returns a GitHub App manifest and the form action to create the app:

```json
{
  "form_action": "https://github.com/settings/apps/new",
  "manifest": {
    "name": "icefall-a1b2c3d4",
    "url": "https://icefall.example.com",
    "default_permissions": { "contents": "read", "metadata": "read", "pull_requests": "write" },
    "default_events": ["push", "pull_request"]
  },
  "webhooks_active": true,
  "instance_url": "https://icefall.example.com"
}
```

### List and delete apps

```
GET /github/apps
DELETE /github/apps/{id}
```

```json
{
  "data": [
    {
      "id": "gha_01",
      "name": "icefall-a1b2c3d4",
      "app_id": 123456,
      "client_id": "Iv1.abc123",
      "html_url": "https://github.com/apps/icefall-a1b2c3d4",
      "owner_id": "usr_nick",
      "created_at": "2026-05-10T10:00:00Z",
      "updated_at": "2026-05-10T10:00:00Z"
    }
  ]
}
```

Secrets and private keys are never serialized.

### App events

```
POST /github/events
```

The endpoint GitHub Apps deliver to. Required headers are `X-GitHub-Event`
(`installation`, `push`, `pull_request`, or `ping`) and `X-Hub-Signature-256`.
The signature is validated against each configured GitHub App's webhook secret
until one matches. `push` events are matched to an Icefall app by clone URL.
Responses: `200` processed, `400` invalid JSON, `401` invalid signature.
